# AI-bypass Manager 1.1.0

**AI-bypass Manager** — единый инструмент обхода региональных блокировок для ChatGPT, Claude, Gemini и Google Antigravity.

>### **WARNING!**
> **Важное предупреждение о совместимости:**
> Данная программа **несовместима** с `antigravity-bypass-russia`.
>
> - Для корректной работы, если у вас ранее был установлен `antigravity-bypass-russia`, **полностью отключите** перед использованием AI-bypass Manager для исключения любых конфликтов, т.к. обе программы используют одинаковые методы обхода.
> - Если это не помогло или в процессе работы что-то сломалось — выполните **чистую переустановку Antigravity**.
> - Скрипт работает при **отсутствии Antigravity**, однако при последующей установке Antigravity, следует сначала **удалить обход**, а после установки Antigravity **установить обход заново**.


Работает исключительно на стандартной библиотеке Python без необходимости установки сторонних пакетов (`pip install`). Весь функционал сосредоточен в одном файле — `ai_bypass.py`.

> Проект вырос из идеи [**vezlin1 / antigravity-bypass-russia**](https://github.com/vezlin1/antigravity-bypass-russia) — эволюционировав от CLI-патчера `antigravity-bypass-russia.exe` до полностью автономного Python-движка со встроенным DoH-форвардером, SNI-пиннингом и удобным управлением установкой и удалением.

## Возможности

- **Установка и удаление в одно действие.** Отсутствует необходимость настраивать браузеры и среды разработки отдельно: пункт `[1]` производит комплексную установку, а пункт `[3]` выполняет полный откат изменений.
- **ChatGPT + Claude** — маршрутизация через Comss SmartDNS (NRPT-правило `AI-Bypass-SmartDNS`).
- **Gemini + Antigravity API** — прямое обращение к substituter-NS (geohide / Comss) с автоматическим переключением (fallback) на локальный DoH-форвардер.
- **Google Antigravity Cloud Code** — SNI-пиннинг рабочего IP через geohide DNS, файл `hosts` и выделенный `/32` маршрут через физический интерфейс.
- **Локальный DoH-форвардер (RFC 8484)** на `127.0.0.1:53` с кэшированием по минимальному TTL, механизмом UDP-fallback и регистрацией в планировщике задач Windows (`ONLOGON /RL HIGHEST`).
- **Патч `language_server`** (архитектуры x64 и ARM64) — устраняет региональное ограничение `User location is not supported`.
- **Единое NRPT-правило для Google AI** — объединённое пространство имён без взаимных пересечений.
- **NODATA для AAAA/SVCB/HTTPS** на доменах Google — исключает зависание браузера из-за таймаутов Happy Eyeballs при попытке подключения по IPv6.
- **Автоматическое восстановление форвардера** — запуск процедуры `ensure_forwarder_if_needed()` при открытии меню.
- **Самовосстановление UDP-сокета** при получении ICMP-сообщений port-unreachable через вызов `WSAIoctl(SIO_UDP_CONNRESET)`.
- **Двухступенчатая запись в файл `hosts`** — атомарная замена через `os.replace`, а в случае отказа Windows — перезапись на месте со снятием атрибута «только чтение».
- **Интерактивная диагностика** — пункт `[4] Details` выводит актуальные статусы DoH-эндпоинтов, substituter-NS, geohide discovery и свежие записи журнала событий.
- **Zero dependencies** — только стандартная библиотека Python 3.8+.

## Что именно делает установка

1. **Проверяет запущенные среды разработки.** При обнаружении активных процессов `antigravity.exe`, `code.exe` или `language_server*.exe` скрипт предложит корректно их завершить.
2. **Тестирует доступные Comss-серверы** (через UDP DNS probe) и выбирает узел с минимальной задержкой из перечня `UPSTREAM_SERVERS`.
3. **Запускает DoH-форвардер** на локальном адресе `127.0.0.1:53` и регистрирует соответствующую задачу в планировщике Windows (`ONLOGON /RL HIGHEST`).
4. **Применяет патч к `language_server`** (для платформ x64 или ARM64) с созданием резервной копии оригинального файла в `.ag-backups/original.bak` и сохранением журнала `current.json`.
5. **Вносит изменения в `settings.json`** — устанавливает параметр `jetski.cloudCodeUrl = https://daily-cloudcode-pa.googleapis.com` во всех обнаруженных конфигурациях IDE (Antigravity, Antigravity IDE, VS Code / Code).
6. **Устанавливает переменную окружения** `CLOUD_CODE_URL`.
7. **Очищает кэш V8 Code Cache** для Antigravity.
8. **Регистрирует правила NRPT:**
   - `AI-Bypass-SmartDNS` → перенаправление трафика ChatGPT и Claude на серверы Comss.
   - `AI-Bypass-DoH` → перенаправление трафика Gemini и Antigravity API на прямые substituter-NS (либо на `127.0.0.1`, если подходящие substituter-NS не обнаружены).
9. **Выполняет поиск substituter-NS** с помощью процедуры `discover_substituters()` — опрашивает серверы geohide и Comss по UDP, определяя серверы имён, которые отдают корректные non-Google A-записи для `gemini.google.com`, `aistudio.google.com` и `generativelanguage.googleapis.com`.
10. **Осуществляет пиннинг Cloud Code:**
    - получение non-Google IP-адресов через geohide DNS;
    - проверка TLS-рукопожатия с передачей корректного SNI хоста;
    - внесение первого подтверждённого рабочего IP в файл `hosts` между метками `# BEGIN AI-Bypass-CloudCode` и `# END AI-Bypass-CloudCode`;
    - добавление прямого маршрута `/32` через основной шлюз системы.
11. **Сбрасывает системный кэш DNS.**

## Как это работает

### NRPT (Name Resolution Policy Table)

В системе формируются два специализированных правила:

| Описание | Обслуживаемые домены | Сервер имён (Nameserver) |
|---|---|---|
| `AI-Bypass-SmartDNS` | ChatGPT, Claude | Сервер Comss SmartDNS (узел с минимальной задержкой из `UPSTREAM_SERVERS`) |
| `AI-Bypass-DoH` | Gemini + Antigravity API | Прямые substituter-NS, либо локальный адрес `127.0.0.1` (DoH-форвардер) |

Доменные имена для сервисов Google AI объединены в общий список `GEMINI_DOMAINS + ANTIGRAVITY_DOMAINS`, что исключает конфликты пространства имён `generativelanguage.googleapis.com`.

### Локальный DoH-форвардер

- Принимает входящие запросы на адресе `127.0.0.1:53` (протокол UDP).
- Обращается к DoH-эндпоинтам `dns.dns-ai.ru/dns-query`, `dns-ai.ru/dns-query`, `dns.comss.one/dns-query` (стандарт RFC 8484, метод POST с заголовком `application/dns-message`).
- Выполняет процедуру bootstrap по фиксированным IP-адресам из `DOH_BOOTSTRAP` для предотвращения циклических зависимостей при разрешении имён DNS.
- Поддерживает кэширование по минимальному значению TTL (ёмкость до 4096 записей).
- При недоступности DoH автоматически переключается на fallback по протоколу UDP: для доменов Google приоритет отдаётся geohide (получение non-Google ответов), затем серверам Comss.
- В ответ на запросы типов `AAAA`, `SVCB` и `HTTPS` для доменов Google возвращает статус `NOERROR/NODATA`, благодаря чему приложения не испытывают задержек при попытках IPv6-соединения.
- Отключает флаг `SIO_UDP_CONNRESET`, предотвращая сброс UDP-сокета при получении пакетов ICMP port-unreachable.
- Регистрирует автоматический запуск через планировщик задач Windows (`AIBypass-DoH`, триггер `ONLOGON`, уровень привилегий `/RL HIGHEST`).
- Процедура `ensure_forwarder_if_needed()` при каждом открытии меню проверяет наличие привязки NRPT к адресу `127.0.0.1` и при необходимости инициализирует запуск форвардера.

### SNI-пиннинг Cloud Code

Для конечных точек `daily-cloudcode-pa.googleapis.com` и `cloudcode-pa.googleapis.com`:

1. Выполняется запрос к DNS-серверам geohide (`45.155.204.190`, `37.230.192.51`).
2. Фильтруются A-записи, не принадлежащие диапазонам IP компании Google.
3. Производится TLS-проверка каждого кандидата с передачей соответствующего SNI.
4. Первый успешно ответивший IP-адрес прописывается в системный файл `hosts` и для него создаётся прямой `/32` маршрут через физический сетевой интерфейс.

Данная цепочка действий позволяет обойти региональный отказ `User location is not supported` без использования сторонних VPN-сервисов.

### Модификация `language_server`

Поиск сигнатур осуществляется по двум шаблонам:

- **x64:** `80 78 08 00 74 ?? 48 8b ?? 24 ?? 48 89 ?? 60` → `c6 40 08 01 90 90 48 8b ?? 24 ?? 48 89 ?? 60`
- **ARM64:** целевой байткод заменяется на последовательность `23 00 80 52 03 20 00 39`

Система резервирования:

- `.ag-backups/original.bak` — неизменённый исходный бинарный файл.
- `.ag-backups/current.json` — журнал состояний (контрольные суммы SHA256 оригинального и модифицированного файлов, профиль `mgr-gate-v1`).

В случае официального обновления приложения старая резервная копия архивируется с именем `original.bak.<sha12>.old`, после чего формируется актуальный бэкап.

## Диагностика

**Пункт `[4] Details`** предоставляет полную сводку о состоянии компонентов:

- Список всех обнаруженных бинарных файлов `language_server` и их текущий статус (`patched` / `stock` / `unrecognized`).
- Состояние локального DoH-форвардера и статус задачи автозапуска.
- Список действующих правил NRPT с назначенными серверами имён.
- Записи в системном файле `hosts` внутри целевого блока маркеров.
- Активные маршруты `/32` для Cloud Code.
- Результаты прямого geohide discovery для хостов Cloud Code.
- Результаты опроса substituter-NS для домена `gemini.google.com`.
- Состояние доступности каждого DoH-эндпоинта.
- Последние 15 строк журнала `server.log`.

**Решение возможных проблем:**

- `[BROKEN] → DoH forwarder is down!` — правило NRPT указывает на адрес `127.0.0.1`, но локальный форвардер не активен. Перезапустите меню (сработает автоматический запуск `ensure_forwarder_if_needed()`) либо повторно выберите пункт `[1]`.
- `DoH forwarder failed to start` / `FATAL bind` — порт `127.0.0.1:53` занят сторонней службой (`SharedAccess` / общий доступ к подключению ICS, Docker Desktop и др.). Завершите работу конфликтующей программы либо перезагрузите систему.
- `hosts write failed` — системе не удалось зафиксировать изменения в файле `hosts`. Ознакомьтесь с записями в конце файла `%LOCALAPPDATA%\AIBypass\doh\server.log`.
- `No substituter and no DoH` — ни один сервер имён не вернул альтернативные non-Google IP-адреса, а протокол DoH недоступен. В таких условиях доступ к Gemini и Antigravity API не сможет быть установлен.
- `backup_unreadable` — резервная копия бинарного файла повреждена. Процесс установки пропускает модификацию данного файла для предотвращения потери оригинальных данных.

## Известные ограничения

- **DoH-эндпоинты `dns.dns-ai.ru/dns-query`, `dns-ai.ru/dns-query` и `dns.comss.one/dns-query`** по состоянию на 14.10.2026 возвращают `HTTP 404` и несоответствие SSL-сертификата соответственно. В этом режиме форвардер функционирует в качестве UDP-прокси с приоритетом geohide для доменов Google.
- **`cloudcode-pa.googleapis.com`** (без префикса `daily-`) не пиннится — служба geohide возвращает для него стандартные IP-адреса Google. Это не влияет на работоспособность, так как конфигурация `settings.json` перенаправляет IDE непосредственно на адрес `daily-`.
- **Конфликты за порт `127.0.0.1:53`** со службой `SharedAccess` (ICS) или Docker Desktop приводят к ошибке `FATAL bind`, при этом правила NRPT продолжают функционировать через прямые NS-серверы.
- **Поддержка macOS и Linux** — нативная реализация в рамках единого скрипта запланирована в последующих версиях (скрипты для macOS и наработки для Linux доступны в репозитории [vezlin1 / antigravity-bypass-russia](https://github.com/vezlin1/antigravity-bypass-russia)).

## Удаление

Пункт `[3] Remove AI Bypass` выполняет полный откат внесённых изменений:

1. Восстанавливает оригинальные файлы `language_server` из резервных копий.
2. Удаляет системную переменную среды `CLOUD_CODE_URL`.
3. Восстанавливает исходные файлы `settings.json` из бэкапов.
4. Выполняет очистку кэша V8 Code Cache.
5. Удаляет все правила NRPT с префиксом комментария `AI-Bypass-*` (включая устаревшие legacy-записи).
6. Сбрасывает системный кэш DNS.
7. Удаляет блок записей Cloud Code из файла `hosts` и зарегистрированные `/32` маршруты.
8. Удаляет назначенное задание `AIBypass-DoH` из планировщика задач (Task Scheduler).
9. Завершает работу локального процесса DoH-форвардера.
10. Удаляет служебную директорию `%LOCALAPPDATA%\AIBypass\` (включая резервные копии `settings-backup\` и каталог DoH-форвардера `doh\`).

После завершения процедуры отката **перезапустите браузер и IDE** (желательно перезагрузить ПК).

<details>
<summary><b>1. Нужно ли держать окно скрипта открытым после выбора [1] Install AI Bypass?</b></summary>

**Нет.** После завершения установки консольное окно можно закрыть. DoH-форвардер запускается как независимый фоновый процесс через `pythonw.exe` и регистрируется в планировщике задач Windows (`AIBypass-DoH`) для автоматического старта при каждом входе в систему.
</details>

<details>
<summary><b>2. Влияет ли программа на скорость обычного интернета или онлайн-игры?</b></summary>

**Нет.** Правила NRPT и маршруты `/32` нацелены исключительно на домены AI-сервисов (ChatGPT, Claude, Gemini, Cloud Code). Все остальные сайты, загрузки и сетевые сервисы идут через обычный DNS вашего интернет-провайдера.
</details>

<details>
<summary><b>3. Что делать при ошибке «DoH forwarder failed to start» или «FATAL bind»?</b></summary>

Это означает, что порт `127.0.0.1:53` занят другой программой (например, Docker Desktop, служба ICS/SharedAccess или локальный DNS-сервер). Завершите работу конфликтующего приложения. Даже если локальный DoH остановлен, скрипт настраивает доступ к Gemini и Claude через прямые substituter-NS.
</details>

<details>
<summary><b>4. Что делать после официального обновления Antigravity или VS Code?</b></summary>

При обновлении среды разработки файл `language_server` перезаписывается стоковой версией. Запустите `ai_bypass.py` и снова выберите пункт `[1] Install AI Bypass` — скрипт автоматически обновит резервную копию и применит актуальный сигнатурный патч.
</details>
